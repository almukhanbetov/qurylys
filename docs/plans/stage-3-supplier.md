# План реализации этапа 3 «Кабинет поставщика»

Основание: [решения S, C, R, N](../decisions/supplier-stage-3.md). Редакция с учётом N1–N5. Приёмка: [supplier-stage-3-acceptance.md](../testing/supplier-stage-3-acceptance.md). **Состояние: 3.1–3.3 в `main` и на production (27.11.2026). Локально, без коммита: часть 3.5 — правка, подтверждение GTIN старых карточек и блокировка карточек, а также администрирование ([решения 8б](../decisions/supplier-stage-3.md)). Публичного показа предложений (3.4), C8 и C10 нет; 3.6–3.7 не начаты.** Имена таблиц, полей и маршрутов — проектные.

## Границы

Входит: предложения поставщика, заявки и модерация карточек, артикулы и GTIN, уровни цен и упаковка, отделение демо, **показ опта проверенной компании-покупателю (N1)**. Фото и документы товара — обязательная часть этапа с отдельным решением (N5).

Не входит: корзина и заказы, оплата, доставка, ERP, тарифы, блокировка отдельного предложения (R6), назначаемое сотруднику право (S2.3), правка наборов характеристик в интерфейсе (R11). Категории в интерфейсе — с 28.11.2026 входят ([A1](../decisions/supplier-stage-3.md)).

**Закрытые цены отдаёт один маршрут** (раздел 2): вошедшему члену выбранной проверенной компании-покупателя. Публичные ответы одинаковы для всех и к таблице опта не обращаются.

## 1. Схема БД и переход данных

Три расширяющие миграции; существующие строки не удаляются.

### 00009 — карточки, права, заявки

| Объект | Содержание |
|---|---|
| `platform_permissions` | `user_id`, `permission` (CHECK `'catalog.moderate'`), `granted_at`. Отдельно от `platform_roles`: разрешение, а не роль (C2) |
| `products.catalog_seq` | `BIGINT GENERATED ALWAYS AS IDENTITY` |
| `products.catalog_no` | вычисляемый столбец из `catalog_seq` (например, `QB0000001`), UNIQUE. Присваивает база, изменить нельзя (R1) |
| `products.gtin` | только подтверждённый, 14 цифр с ведущими нулями, UNIQUE, CHECK контрольной цифры |
| `products.gtin_source_kind`, `gtin_source`, `gtin_confirmed_at`, `gtin_confirmed_by` | изготовитель / упаковка / официальный каталог; заполнены тогда и только тогда, когда есть GTIN |
| `products.needs_review` | по умолчанию TRUE: старые и демо-карточки требуют проверки (C4) |
| `products.blocked_at`, `block_reason` | блокировка; причина обязательна (R6) |
| `catalog_requests` | заявка: компания, автор, поля карточки, заявленный GTIN и источник, статус, `submission_no`, снимок, комментарий, `product_id` после одобрения. Переходы и обязательный комментарий — триггером, как в 00008 |
| `catalog_events` | журнал только на добавление: заявки, правки, GTIN, блокировки; кто, когда, старое и новое, причина |

### 00010 — предложения

| Поле `offers` | Правило |
|---|---|
| `owner_state` | `draft` / `published` / `hidden` — выбор владельца (C8) |
| `seller_sku` | UNIQUE (`supplier_company_id`, `lower(seller_sku)`); для публикации обязателен |
| `vat_status` | `with_vat` / `without_vat`; для публикации обязателен |
| `pack_size` | `NUMERIC(14,3) > 0`, базовых единиц в упаковке; одна схема на предложение (R9) |
| `retail_sale_mode` | `piece` / `pack` для РРЦ (N6) |
| `price_tiyn`, `min_order_quantity` | остаются как РРЦ и её минимум; смысл не меняется |
| `version` | оптимистичная блокировка цены и остатка (ТЗ §15, с. 15) |

`offer_price_tiers` (`offer_id`, `level` = `wholesale` / `large_wholesale`, `price_tiyn`, `min_quantity`, `sale_mode`, UNIQUE по уровню; способ, минимум и шаг — у уровня, N6) — **отдельная таблица**: публичные запросы к ней не обращаются. `offer_events` — журнал цен, остатка и публикации.

Ограничения базы:

- **Штучные единицы** (`piece`, `bag`, `pack`, `roll`, `sheet`, `pallet`): остаток, минимумы и `pack_size` — целые; поштучный шаг 1.
- **Измеряемые** (`kg`, `tonne`, `m`, `m2`, `m3`, `litre`): точные десятичные до 3 знаков (`NUMERIC(14,3)`).
- Уровень со способом `pack`: минимум и шаг этого уровня кратны `pack_size` в точной десятичной арифметике, иначе отказ без округления (R10). Дробный тиын в сумме **не** причина отказа (N4).
- Одно предложение компании на карточку — действующий `offers_product_supplier_key` (R9).
- `offers.is_demo` = `companies.is_demo`; для настоящего предложения карточка не демо. Менять `is_demo` запрещено триггером (C5).
- `products.unit` и `gtin` нельзя менять при любых связанных предложениях, включая черновики (R11).
- Снятие `is_supplier`: триггер переводит `published` → `hidden` (C10 + C8).

### 00013 — единое условие показа (00011 — администрирование каталога, 00012 — справочник ролей)

Представление `public_offers`: настоящие предложения, у которых одновременно `owner_state = 'published'`, компания активна, поставщик и проверена, карточка активна, не заблокирована, `needs_review = FALSE`, GTIN подтверждён. Столбцы перечислены явно, опта среди них нет. Список, минимальная цена, поиск и страница товара читают только его (D1).

### Безопасный переход и откат

1. **Отчёт до миграции (C4).** Команда только на чтение `admin catalog-report`: настоящие и демо-товары и предложения, карточки без GTIN, предложения, которые перестанут показываться, дубли названий. Без персональных данных. Решение о выпуске — после отчёта.
2. **Старое поле `is_active`.** После перехода TRUE только у демо: CHECK `is_demo OR NOT is_active`. Значение `is_active` настоящих предложений сначала переносится в `owner_state` (`hidden` для активных, `draft` для остальных: без артикула и НДС публиковать нельзя, владелец решает сам). Поэтому **прежний образ после отката не покажет** черновики, скрытые и непроверенные предложения: он фильтрует по `is_active`. Цена — при откате настоящие предложения временно не видны.
3. GTIN, `seller_sku` и НДС не выдумываются: остаются пустыми.
4. Добавление `catalog_seq` переписывает `products` под короткой блокировкой. Прототип проверен на одноразовом PostgreSQL 16 с миграциями 00001–00008 и демо-данными: прежние столбцы не изменились, 17 номеров уникальны, повторный seed работает, роль без прав на последовательность вставляет строки, изменить номер нельзя. Номера могут идти с пропусками (повторный seed их расходует): порядковый смысл артикулу не придавать.

## 2. API и проверки прав

Ответы — `no-store`, изменения — CSRF, ограничение частоты и аудит.

| Маршрут | Кто | Проверка |
|---|---|---|
| GET `/companies/:id/offers`, `/:offerId` | владелец и сотрудник (N2) | `companies.Authorize`, активная компания |
| GET `/companies/:id/prices?product_id=` | член проверенной компании-покупателя (N1) | членство, активная компания, `status = 'active'`, `is_buyer`, действующая проверка — на каждый запрос; `no-store`; только `public_offers` |
| POST, PUT `/companies/:id/offers` | владелец поставщика | черновик и непроверенной; `version` в PUT → 409 |
| POST `…/publish`, `…/hide` | владелец | публикация: все условия; невыполненные — в поле `reasons` предложения |
| GET `/companies/:id/offer-cards` | владелец | только одобренные настоящие карточки |
| GET `/companies/:id/catalog-requests` | владелец; сотрудник — требует уточнения, до решения запрещено | N2 говорит о просмотре предложений, но не заявок |
| POST, PUT `/companies/:id/catalog-requests`, `…/submit` | владелец поставщика | GTIN заявлен, источник указан (C1) |
| GET `/catalog/moderation/requests`, `/:id` | `catalog.moderate` | конфликт интересов |
| POST `/catalog/moderation/requests/:id/decision` | `catalog.moderate` | `submission_no`, блокировка строки; одобрение требует подтверждённого GTIN и обязательных данных (R2) |
| PATCH `/catalog/moderation/products/:id`; POST `…/gtin`, `…/block`, `…/unblock` | `catalog.moderate` | причина, журнал, конфликт |
| PUT `/admin/users/:id/catalog-moderate` | `admin` | выдача и отзыв, в том числе себе; аудит (R4) |

- **Сотрудник (N2):** просмотр предложений своей компании; любое изменение — 403. Исключение из компании действует сразу.
- **MRX без членства:** 403 на изменение предложений (BR-13), одинаково для существующих и несуществующих id. Остальные посторонние — 404. MRX, который сам владелец, действует как владелец: права независимы (R3).
- **Независимость прав (R3).** `mrx`, `catalog.moderate`, `admin` и членство проверяются порознь, в транзакции действия; отзыв действует сразу.
- **Конфликт интересов** — на каждое действие: своя заявка; заявка компании, где пользователь состоит или состоял (R5). Для действий с карточкой — то же по компании-заявителю **и по любой компании, чьё предложение связано с карточкой**: иначе модератор мог бы заблокировать или изменить карточку в пользу своей компании. Условие берётся из `verification.conflictSQL`, выносится в общий пакет.
- **GTIN** принимается в длинах 8, 12, 13, 14, проверяется контрольная цифра, хранится в 14 знаках. Совпадение с подтверждённым GTIN другой карточки — отказ и ссылка модератору. Технические проверки не заменяют подтверждение источника.
- **Одобрение** создаёт карточку (или связывает с существующей, если это дубль). Предложение поставщика при этом **не создаётся и не публикуется** (R2).
- **Правка карточки (N3).** Модератор указывает вид и причину; старое и новое — в журнале.
  - *Косметическая:* описание, опечатка и форматирование названия или бренда. Показ не меняется.
  - *Существенная* (товар, вариант, фасовка, GTIN, единица) при связанных предложениях запрещена и API, и триггером для структурных полей: единица, GTIN, категория, характеристики, помеченные в наборе как определяющие вариант (объём, марка и т. п.).
  - *Контролируемое исправление:* блокировка ошибочной карточки с причиной → новая карточка → владельцы **сами** создают предложения на ней. Старые остаются при старой карточке. Без связанных предложений допустима прямая правка с аудитом.

## 3. Кабинеты

**Поставщик** (`/account/offers`, `/account/catalog-requests`; только при направлении «Поставщик», управление — владелец):

- Сотрудник видит те же экраны без кнопок изменения.
- Список: артикул каталога и отдельно «Ваш артикул», выбор владельца, фактическая доступность и **причины, почему не показывается**.
- Мастер: поиск карточки → продажа и упаковка → РРЦ и минимум → опт и крупный опт → НДС → остаток и город. Стоимость упаковки показывается как расчётная: цена × размер, half-up до тиына; без `float` (в браузере — целые/`BigInt`).
- Заявка на товар: GTIN и источник, статусы, замечания, повторная отправка.
- Предупреждение безопасности ТЗ §13 (с. 14) в форме предложения; подпись «доставка не входит в цену» (C9).
- Снятие направления — подтверждение с объяснением последствий (C10).

**Модератор** (`/account/catalog-moderation`; по праву):

- Очередь заявок с фильтром, снимок заявки, похожие карточки (GTIN, название, бренд), решение с комментарием.
- Карточка: правка, подтверждение GTIN с источником, блокировка с причиной, журнал, число связанных предложений. Цены поставщиков модератору не показываются.
- Очередь «требует проверки» для старых карточек.

**Администратор:** выдача и отзыв `catalog.moderate` рядом с MRX, с подтверждением при выдаче себе. Все экраны — KZ/RU, 360 px, состояния загрузки, ошибки и пустоты.

## 4. Публичный каталог и поиск

- `min_price` и `offer_count` — только из `public_offers`. Добавляются `demo_min_price`, `catalog_no`, `gtin`.
- Нет настоящих предложений — текст «Настоящих предложений пока нет» и отдельно «Демонстрационная цена» (R7). Если настоящие есть, демо-цены остаются в отдельном блоке страницы товара.
- Сортировка по цене и по числу предложений — только по настоящим. Карточки без них идут в конце.
- Страница товара: настоящие и демо — раздельными списками. Порядок: доступные по РРЦ, затем недоступные. Доступность РРЦ — её минимум, кратность и остаток; недоступный опт розницу не скрывает (C6).
- Поиск: название, бренд, `catalog_no`, подтверждённый GTIN, `seller_sku` **только** через `public_offers`. Скрытое предложение не меняет ни выдачу, ни `total`.
- Заблокированная карточка: 404 и исключение из списка и счётчиков категорий. Владелец и модератор видят её в кабинетах.
- **Опт (N1):** страница товара запрашивает `/companies/:id/prices` из браузера после загрузки; в HTML, SSR-данных и метаданных его нет. При выходе, смене компании или снятии проверки — полная перезагрузка или 403/401, цены убираются. Сравнение — на каждом доступном уровне отдельно; список каталога и его сортировка — только РРЦ.
- Кэш: публичные ответы не зависят от пользователя и не содержат закрытых полей; кабинетные — `no-store`. SSR не запрашивает кабинетные данные на публичных страницах.

## 5. Обязательные проверки

| Область | Случаи |
|---|---|
| Цены | тиыны, переполнение при умножении, 0 и отрицательные; half-up; строка округляется один раз; итог — сумма строк |
| Примеры N4 | 12 шт. × 1 500 ₸ = 18 000 ₸; 500 кг × 84,37 ₸ = 42 185 ₸; 0,6 м³ × 833,33 ₸ = 499,998 → **500,00 ₸**; граница: 0,5 × 1 тиын = 0,5 → 1 тиын, а 2 × 0,5 × 1 тиын = 1 тиын, не 2 |
| Упаковка | 5 × 12 = 60; минимум 50 при 12 — отказ; 1,5 шт. — отказ; 1,5 м³ — допустимо; минимум 1,2 м³ при упаковке 0,6 — допустимо, 1,0 — отказ; остаток 59 при минимуме 60: опт недоступен, розница доступна |
| Доступ к опту | гость; вошедший без компании; непроверенная; проверенная без «Покупателя»; проверенный покупатель: владелец, сотрудник; исключённый; другая активная компания; проверка снята в открытой вкладке |
| GTIN | длины, контрольная цифра, ведущие нули, дубль, неподтверждённый, одобрение без него |
| Конфликт | своя заявка; член, бывший член; связанная с карточкой компания; отзыв права во время действия |
| Права | владелец, сотрудник, посторонний, MRX, `admin` без права, модератор, MRX + модератор |
| Показ | по одному снять каждое условие `public_offers`; вернуть; скрытое не возвращается; C8 и C10 по отдельности и вместе |
| Демо | обычная компания не может получить или выдать `is_demo`; демо не в минимальной цене и сортировке |
| Утечки | опт вне `/companies/:id/prices`: список, карточка, предложения, поиск, метаданные, заголовки кэша; скрытые `seller_sku`, черновики: список, карточка, предложения, поиск, `total`, HTML, SSR-данные |

5. Выдать `catalog.moderate`; минимум два модератора из разных компаний, см. ниже.
6. Откат: `rollback --force-schema`; настоящие предложения временно не видны, данные сохраняются. Миграции вниз не выполнять.

## Сценарии, о которых нужно помнить

Начало работ не блокируют.

1. **Единственный модератор связан с компанией** — нужен второй, не связанный.
2. **Существенная правка под видом опечатки.** «750 мл» → «500 мл» в названии система автоматически не отличит. Защита: определяющие вариант характеристики закрыты, причина и обе версии в журнале.
3. **Шаг измеряемого товара.** Решения не задают шаг при продаже без упаковки; по умолчанию точность 0,001 единицы.
4. **Сотрудник и заявки на товары.** N2 разрешает просмотр предложений; просмотр заявок не упомянут — по умолчанию запрещён.
5. **GTIN упаковки и штуки различаются:** на карточке один основной GTIN (ТЗ §06, с. 9).
6. **Характеристики товара.** Централизованные наборы (S3.6) ещё не заведены, поэтому в заявке их нет.
7. **Непроверенный поставщик** может подать заявку на товар: решения ограничивают публикацию предложений, а не заявки.
