# Пользователи, компании и права (этап 1)

## Модель

- **users** — только подтверждённые пользователи: запись появляется после ввода кода. Контакт — email или телефон +7.
- **companies** — та же таблица, что у каталога; добавлены юридический и фактический адрес, рабочий телефон, представитель.
- **company_members** — членство с ролью `owner` или `employee`. Пользователь может состоять в нескольких компаниях; последнего владельца убрать нельзя.
- **sessions.active_company_id** — активная компания этой сессии. Составной внешний ключ не даёт выбрать чужую компанию; при исключении из компании выбор сбрасывается.
- **company_invitations** — приглашение на контакт. Видит его только тот, кто подтвердил этот контакт. Сообщения не отправляются.
- **platform_roles** — `mrx`, `admin`. Отдельны от компаний и не дают доступа к данным компаний.
- **audit_events** — журнал, изменение и удаление запрещены триггером.

| Действие | Владелец | Сотрудник | MRX | Администратор |
|---|---|---|---|---|
| Смотреть компанию и состав | да | да, без контактов | нет | нет |
| Менять компанию, роли, приглашать | да | нет | нет | нет |
| Заявка на проверку: создать, документы, отправить | да | нет, только статус | нет | нет |
| Смотреть и решать чужие заявки | нет | нет | да, кроме своих компаний | нет |
| Выдавать и снимать MRX | нет | нет | нет | да |
| Выдавать администратора | — | — | — | только команда `admin` |

## Проверка доступа

`companies.Authorize`: членство (иначе 404) → компания из URL совпадает с активной (иначе 409 `company_context_mismatch`) → роль (403) → компания не приостановлена (403).

## Безопасность

- Пароли: argon2id (19 МиБ, t=2), 10–128 символов, список простых запрещён.
- Сессия: случайный токен в HttpOnly SameSite=Lax cookie (в production `__Host-`, Secure), в БД SHA-256. 30 дней максимум, 7 дней без активности. Сброс пароля завершает все сессии, смена — остальные.
- CSRF: обязательный заголовок `X-Qurylys-Csrf: 1` и проверка `Origin`/`Sec-Fetch-Site`.
- Коды: 6 цифр, 15 минут, 5 попыток, одноразовые. В БД HMAC с ключом, который есть только у клиента.
- Лимиты (PostgreSQL): вход — 8 на пару адрес+контакт, 40 на контакт, 100 на адрес за 15 минут; отправка — 5 за 15 минут и 15 в сутки на контакт, 30 в час на адрес, всего писем — `EMAIL_DAILY_LIMIT` в сутки; проверка кодов — 60 за 15 минут на адрес.
- Регистрация и восстановление не раскрывают, занят ли контакт.

## Доставка кодов

Интерфейс `delivery.Sender`. Реализации: `disabled` (по умолчанию), `local` (файл 0600, запрещён в production) и `smtp` (email, [email.md](email.md)). SMS нет: в режиме `smtp` телефон подтвердить нельзя (`channel_unavailable`). Отправка — быстрая постановка в очередь, иначе время ответа выдаст существующие контакты.

## API

Ошибки полей: `invalid_<поле>`. Все изменяющие запросы требуют `X-Qurylys-Csrf: 1`.

| Метод и путь | Назначение |
|---|---|
| GET `/auth/options` | какие каналы подтверждения доступны |
| POST `/auth/register`, `/auth/register/confirm` | регистрация |
| POST `/auth/login`, `/auth/logout` | вход, выход |
| POST `/auth/password/forgot`, `/auth/password/reset` | восстановление |
| GET, PATCH `/me` | профиль |
| POST `/me/password`, `/me/contacts`, `/me/contacts/confirm` | пароль, контакты |
| GET `/me/sessions`, DELETE `/me/sessions/:id`, POST `/me/sessions/revoke-others` | сессии |
| PUT `/me/active-company` | выбор компании |
| GET `/me/invitations`, POST `/me/invitations/:id/accept` и `/decline` | приглашения мне |
| POST `/companies`, GET и PUT `/companies/:id` | компания |
| GET `/companies/:id/members`, PATCH и DELETE `/companies/:id/members/:userId` | состав |
| GET и POST `/companies/:id/invitations`, DELETE `/companies/:id/invitations/:invitationId` | приглашения |
| GET `/admin/users`, PUT `/admin/users/:id/mrx` | администратор |

## Ограничения

- БИН уникален, но при создании компании не проверяется: его может занять чужая компания. Такую заявку отклонит MRX ([verification.md](verification.md)), но освободить БИН в интерфейсе пока нельзя.
- У администратора нет второго фактора (ТЗ §12 требует MFA для SA).
- Нет согласия на обработку персональных данных: нужен юридический текст.
