# Отправка email (Gmail SMTP)

Режим `CONTACT_DELIVERY=smtp`. Коды регистрации, восстановления и смены контакта уходят письмом на языке интерфейса (kk/ru). Локальный режим `local` остаётся режимом по умолчанию в Docker-стеке.

## 1. Подготовка ящика

1. Выберите отдельный Gmail-ящик для писем сервиса.
2. Включите двухэтапную аутентификацию: Google Аккаунт → Безопасность.
3. Создайте пароль приложения: https://myaccount.google.com/apppasswords. Google покажет 16 символов один раз. Запишите их **без пробелов**.
   - Страницы нет: не включена двухэтапная аутентификация, включена «Дополнительная защита» или пароли приложений запретил администратор Workspace.
4. Обычный пароль аккаунта не используйте: Gmail его не примет, и попадать в env он не должен.

## 2. Переменные

| Переменная | Значение |
|---|---|
| `CONTACT_DELIVERY` | `smtp` |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_TLS` | `smtp.gmail.com`, `587`, `starttls` |
| `SMTP_USERNAME` | адрес ящика целиком |
| `SMTP_PASSWORD` | пароль приложения, **секрет** |
| `SMTP_FROM` | тот же адрес (по умолчанию = `SMTP_USERNAME`) |
| `SMTP_FROM_NAME`, `SMTP_REPLY_TO` | имя отправителя; адрес ответа (необязательно) |
| `EMAIL_DAILY_LIMIT` | 400 — общий предел запросов кода в сутки |

Неполные настройки и незашифрованный SMTP не дают API запуститься. Пароль не пишется в логи и ошибки.

## 3. Проверка локально

Отредактируйте корневой `.env` (он в `.gitignore`), затем:

```bash
chmod 600 .env
docker compose up -d --build api web nginx
docker compose exec api admin test-email -contact <ваш адрес>
```

Вернуться к тестовому файлу: `CONTACT_DELIVERY=local` и `docker compose up -d api`.

## 4. Production (при отдельной задаче на деплой)

Порядок важен: текущая версия API не знает `smtp`, поэтому переменные добавляются в `/opt/qurylys/env/api.env` (права 600) **перед деплоем новой версии**, а запущенный контейнер не перезапускается вручную.

В `api.env` значения пишутся без кавычек. Заранее проверьте исходящий порт с VPS:

```bash
timeout 5 bash -c '</dev/tcp/smtp.gmail.com/587' && echo open
```

После деплоя:

```bash
cd /opt/qurylys
docker compose --env-file state/current.env -f compose.prod.yml exec -T api admin test-email -contact <адрес>
```

## 5. Если не работает

`test-email` и лог API (`mail delivery failed`) показывают причину без адресов и паролей:

| Причина | Что сделать |
|---|---|
| `smtp reply 534/535` | проверить адрес, создать новый пароль приложения |
| `connection failed`, `timeout` | исходящий порт 587 закрыт у провайдера или нет DNS; попробовать 465 и `SMTP_TLS=tls` |
| `smtp reply 550` | превышен лимит Gmail или адрес не существует |
| `TLS certificate verification failed` | перехват трафика или неверный `SMTP_HOST`; проверку не отключать |
| принято, но письма нет | «Спам»; папка «Отправленные» ящика |

## 6. Поведение и ограничения

- Отправка фоновая, очередь на 200 писем в памяти. Временные ошибки повторяются через 2, 10 и 30 секунд. При остановке API очередь дорассылается в пределах `SHUTDOWN_TIMEOUT`. После аварии код нужно запросить заново: в базе коды в открытом виде не хранятся.
- Если письмо не ушло, посетитель об этом не узнает: ответ одинаков для всех адресов. Следите за `mail delivery failed`.
- У Gmail есть суточный лимит (ориентир — 500 писем для обычного ящика, 2000 для Workspace); при превышении отправка блокируется примерно на сутки. Сверьте актуальные значения в справке Google.
- Смена основного пароля Google отзывает пароли приложений.
- Письма приходят с адреса `@gmail.com`. Для роста лучше ящик на `qurylys-b2b.kz` с SPF, DKIM и DMARC: меняются только переменные.
