# Деньги в QURYLYS

## Решение

Все суммы хранятся и передаются как **целое число тиынов** (1 ₸ = 100 тиын). Валюта на этапе 1 — только `KZT`.

| Слой | Представление | Пример (2 750 ₸) |
|---|---|---|
| PostgreSQL | `BIGINT` (`offers.price_tiyn`), `CHECK (price_tiyn > 0)`, `currency CHAR(3) CHECK (currency = 'KZT')` | `275000` |
| Go | `int64` (`Money{AmountTiyn int64, Currency string}`) | `275000` |
| JSON API | `{"amount_tiyn": 275000, "currency": "KZT"}` | |
| Frontend | `number` → строка через `formatMoney()` (`src/lib/format.ts`), без дробной арифметики | `2 750 ₸` |

## Почему не float и не NUMERIC

- `float` неточен (0.1 + 0.2 ≠ 0.3) — запрещён везде.
- `NUMERIC` точен, но в Go и JSON его пришлось бы передавать строкой или через сторонний decimal-тип. Целые тиыны дают точность, простые сравнения/сортировку и естественный тип во всех трёх слоях.
- Предел: `int64` вмещает ~9,2·10¹⁶ ₸. В JavaScript целые точны до 2⁵³ тиын (~90 трлн ₸) — с запасом для цен за единицу и будущих сумм заказов.

## Правила

- Цена предложения — за **одну единицу измерения товара** (`products.unit`).
- Количества (остаток, минимальный заказ) — `NUMERIC(14,3)` в БД, в API — **десятичная строка** (`"12.75"`), чтобы не терять точность (`trim_scale` убирает лишние нули).
- Умножение цены на количество (этап корзины): делать на сервере в целых тиынах с явным правилом округления; на клиенте — только отображение.
